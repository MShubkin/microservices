# Сквозное логгирование запросов.

Для упрощения задачи анализа логов выполнения микросервисов требуется
возможность их фильтрации по различным критериям. Такими критериями могут быть,
например, идентификатор запроса (чтобы получить все события в разных
микросервисах, относящихся к обработке данного запроса), или идентификатор (id,
uuid) объекта (чтобы получить события всех/некоторых запросов с участием этого
объекта).

Для этого требуется, чтобы каждое событие трассировки/журналирования,
относящееся к пользовательскому запросу, содержало определенный набор полей,
позволяющих это событие идентифицировать соответстующим образом. При
использовании крейта `tracing` удобно воспользоваться объектом `Span`, поля
которого добавляются к каждому дочернему событию.

## Общие поля событий

На настоящий момент следующие поля попадают в корневой `span`:
- Идентификатор HTTP запроса `"asez.request_id"`
- URI запроса `"asez.uri"`
- User agent, выполнивший запрос `"asez.user_agent"`
- IP адрес и порт, откуда произошел запрос `"asez.source_ip"`, `"asez.source_port"`
- Числовой идентификатор и логин пользователя, от имени которого выполнен запрос (`asez.user_id`, `asez.user_name`)
- Категория запроса, пока либо `get` либо `update`, в основном требуется для SIEM (`asez.category`)
- Идентификаторы (числовые и UUID) объектов (ППЗ/ДС, Повестка, Протокол) запроса (`asez.object_ids`, `asez.object_uuids`)

### Идентификаторы объектов

Для того, чтобы проследить историю событий относящихся к заданному объекту, в
событии присутствуют поля `object_ids` и `object_uuids`, содержащие возможно
пустой список целочисленных идентификаторов объектов и UUID'ов. Эти патаметры
получаются из запросов по следующим эвристикам.

- Запрос GET может содержать числовой параметр пути запроса. Если таковой
  имеется, он помещается в `object_ids`.
- Тело запроса POST может содержать JSON объект с полями `id` и/или `uuid`. В
  этом случае они помещаются в `object_ids` и `object_uuids`, соответственно.
- Тело запроса POST может содержать JSON объект вида `{"item_list": [{"id": XXX,
  "uuid": "..."}]}`. В этом случае значения полей `id` и `uuid` помещаются в
  `object_ids` и `object_uuids`, соответственно.


## Передача общих полей микросервисам

В АСЭЗ 2 в обработке одного запроса могут участвовать несколько сервисов. При
этом обмен данными происходит через брокер сообщений. Для того, чтобы события
содержали общие данные запроса в сервисах, не получающих непосредственно
пользовательский HTTP запрос, эти данные также должны передаваться через брокер.
Для этого используется таблица полей из свойства запроса (`TableField`).

После принятия запроса от брокера сообщений сервис создает `span` с
соответствующими полями и вызывает обработчик запроса в рамках этого `span`.
